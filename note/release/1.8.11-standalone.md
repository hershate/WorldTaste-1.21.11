# 1.8.11-standalone

> 性能优化 R8（全维度最终扫描 + 作物收获 total 预算 + 全维度收敛判定），基于 [1.8.10-standalone](1.8.10-standalone.md)。
> 内容 YAML 不变。完整审查与基准见 [../report/perf/PERF-AUDIT.md](../report/perf/PERF-AUDIT.md) 第 8 轮。

## 版本定位
- 版本：`1.8.11-standalone`（[plugin/build.gradle.kts](../../plugin/build.gradle.kts)、[plugin.yml](../../plugin/src/main/resources/plugin.yml)）。
- 收敛轮：复核全部运行期路径，修复一处 R4 模式的一致性遗漏，宣告**静态性能优化全维度收敛**。

## 改动（性能，行为不变）

### R8：全维度最终扫描 + 作物收获 total 预算（对齐 R4）
- **最终扫描**：逐一复核 R1–R5 未深入基准的运行期路径——
  - `MobDropListener.onDeath`：按实体类型索引 + getById O(1) + 独立 chance 滚动 → **已最优**。
  - `WTRecipe.pushOutputs`：`clone()` 必需（base 输出跨多次合成共享，pushItem/setAmount 改堆）→ **R5 判断正确**。
  - `CropBlock.onBreak`：发现**每次收获都重新求和权重 total**（R4 已把同模式在 FishingListener 改为 load 期预算 `Bait.total`，此处遗漏）→ **本轮修复**。
- **优化**：[Behaviors.CropCfg](../../plugin/src/main/java/com/haiman233/worldtaste/behavior/Behaviors.java) 增 `weightTotal`（loadCrops 期预算），[CropBlock.onBreak](../../plugin/src/main/java/com/haiman233/worldtaste/items/CropBlock.java) 用预算值（消除每次收获求和，O(n)→O(1)）。
- **基准**（`HarvestBench`）：n=13（真实 max）**~1.2×**、n=50（stress）**~1.7×**。

## 安全性 / 保真度（红线）
- **分布不变**：预算 `weightTotal = Σweight`（loadCrops 累加，仅含合法项，与原 onBreak 内联求和的 drops 列表同源），`rnd.nextDouble()*total` 产出逐字相同的分布；`total<=0` 守卫与末项兜底不变。
- **作用域**：仅 `weighted=true` 作物（24 个）走该分支；118 个概率作物走独立 chance 滚动，不受影响。

## 全维度收敛判定（R1–R8）
R1–R8 已覆盖**所有可静态分析 + 微基准化**的优化点：

| 维度 | 轮次 |
|---|---|
| per-tick 热路径 | R1/R2（findMatch）、R3（CropBlock.tick）、R8（CropBlock.onBreak） |
| 事件驱动路径 | R4（Fishing total 预算、MobDrop 核查已最优） |
| 低频运行期路径 | R5（getDisplayRecipes 缓存、pushOutputs 评估） |
| 加载期路径 | R6（YAML 解析缓存 ~2×）、R7（头颅贴图去重 ~1.4×） |

剩余均为**不可约**（唯一贴图解码、每物品必需的 ItemStack、加权选择的随机遍历、clone 必需的产出堆）或**需真实服务端 profile**才能显现（cargo 自动化、特定机器配方表实机热点）。
**静态性能优化全维度收敛。**

## 诚实声明
R8 收获优化绝对收益小（低频玩家事件 + 小 n），属零风险一致性修复（对齐 R4）。**后续静态轮次无预期产出**；绝对 TPS/启动耗时需真实 Paper 1.21.11 + Slimefun4.1 + 美食家/异域花园 服务端实测（本环境无服务端）。若实机 profile 发现新热点可再开轮。
