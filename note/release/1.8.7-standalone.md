# 1.8.7-standalone

> 性能优化 R4（事件驱动路径：Fishing total 预算 + getById O(1) 核查），基于 [1.8.6-standalone](1.8.6-standalone.md)。
> 内容 YAML 不变。完整审查与基准见 [../report/perf/PERF-AUDIT.md](../report/perf/PERF-AUDIT.md) 第 4 轮。

## 版本定位
- 版本：`1.8.7-standalone`（[plugin/build.gradle.kts](../../plugin/build.gradle.kts)、[plugin.yml](../../plugin/src/main/resources/plugin.yml)）。

## 改动（性能，行为不变）

### R4：Fishing select 权重 total 预算
- **问题**：`FishingListener.select` 每次钓获都对全部掉落（最大 133 项）求权重和。
- **优化**：`baits` 由 `Map<String,List<Drop>>` 改为 `Map<String,Bait>`，`Bait` 在 load 期预算 `total = Σweight`，
  `select` 直接用预算 total（O(n) 求和 → O(1)）。
- **基准**（`FishingBench`，133 掉落）：**~1.7×**（138→82 ns；余为加权遍历，不可消除）。

### 核查结论（不改动）
- **`SlimefunItem.getById` 为 O(1)**（HashMap 查找，REF SlimefunItem.java:1141-1142）；`getByItem` 对原版物品单次
  Set 查找即返回。故 **MobDrop `getById` 缓存不必要**（仅省一次 map.get，无收益）。
- **回溯确认 R1**：`isItemSimilar` 对 SF 物品每次比较含 1 次 PDC 读取；纯-SF 机器由 31 次→1 次，
  加速比≈调用次数比（稳健），R1 的 ~21× 成立（机制为 PDC 读取次数减少）。

## 安全性 / 保真度（红线）
- `Bait.total` 预算与原每次求和数值相同；RNG（`Math.random`）不变，加权分布逐字一致。
- MobDrop 路径未改动（getById 已 O(1)）。

## 已知差距（沿用）
- 实机加载/运行验证待补（需真实服务端）；基准为算法/分配微基准。
