> 内容 YAML 不变。完整审查与基准见 [../report/perf/PERF-AUDIT.md](../report/perf/PERF-AUDIT.md) 第 3 轮。

## 版本定位
- 版本：`1.8.6-standalone`（[plugin/build.gradle.kts](../../plugin/build.gradle.kts)、[plugin.yml](../../plugin/src/main/resources/plugin.yml)）。

## 改动（性能，行为不变）

### R3：CropBlock.tick 不变量预算 + 候选优化实测验证
- **落地**：`CropBlock` 构造期预算 `double[] growMsSteps = cfg.growMs * SMALL_STEPS[i]`（不变量），
  tick 生长循环改用预算值，消除每个生长作物每 tick 的 8 次 double 乘法。行为逐字一致（double 阈值保精确比较语义）。
- **数据驱动验证（benchmark/CropBench）**：
  - **Location 分配消除方案（pack-long+双层map）经实测为 CPU 劣化（~0.54×，per-tick 翻倍）→ 拒绝**。
    双层 map 两次查询代价 > 一次 Location 分配；虽省 GC，但高负载下损 TPS。记录此负结果以防后续误引入。
  - **map 合并（grown set + lastUse map → 单 map）实测 1.00×（不可测收益）→ 不改**（红线：无收益不改）。
- **加载期非双趟解析**：核查确认 `ItemsLoader.register` 复用 `WT.preload` 展示堆、不重调 `Read.item`，
  故「双趟解析」设想不成立；加载主体为头颅解码（单趟、Bukkit 内部）。

## 安全性 / 保真度（红线）
- `growMsSteps` 预算值与原 `cfg.growMs * SMALL_STEPS[i]` 数值完全相同（double），比较语义不变。
- 拒绝 Location 方案避免了 per-tick CPU 翻倍的劣化；未做无收益的 map 合并。

## 已知差距（沿用）
- 实机加载/运行验证待补（需真实服务端）；本轮基准为算法/分配微基准。
