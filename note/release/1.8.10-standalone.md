## 改动（性能，行为不变）

### R7：启动期 头颅贴图(PlayerSkin)去重缓存
- **背景**：[Read.resolve](../../plugin/src/main/java/com/haiman233/worldtaste/load/Read.java) 对每个 skull_hash/skull/skull_url 调
  `PlayerSkin.fromHashCode/fromBase64/fromURL`（每次含 MD5 `UUID.nameUUIDFromBytes` + JSON + Base64 + URL 解析）。
- **先实测**：skull_hash 解码共 2684 次、仅 178 次（6.6%）重复；核查 dough `PlayerSkin` **无内部缓存** → 外层去重有真实收益。
- **优化**：按 (类型,材质) 缓存 `PlayerSkin`（3 分表，零命中分配、杜绝跨类型键碰撞）；`PlayerHead.getItemStack` 仍每次新建独立 ItemStack（不污染缓存值）。
- **基准**（`SkinBench`，逐字复刻 fromHashCode 的 JDK 工作）：工作次数/加载 **2684→2506**；fromHashCode 段 **~1.4×**。

## 安全性 / 保真度（红线）
- **共享安全**：`PlayerSkin` 不可变（final uuid/texture/url）；`PlayerHead.getItemStack` 每次返回新建 ItemStack、不修改传入 skin → 缓存值永不被污染。
- **行为保真**：缓存的 PlayerSkin 与「重新 fromHashCode」逐字相同（纯函数），产出 ItemStack 一致。
- **释放安全**：grep 确认 `Read.item/recipe` 仅加载期调用（运行期用 SlimefunItem 注册表与 WT.preload），`Setup.loadAll` 末尾 `clearSkinCache` 安全。

## 诚实声明
- 重复率仅 ~6.6%，**绝对收益受限于去重量**；3021 个唯一解码不可约（每独立物品需各自贴图），getItemStack（Bukkit，每唯一物品各一）不可优化。
- 此为「正确的零风险去重」，量级与 R3 微优化、R4/R5 相当。加载期至此趋收敛（R6 解析缓存 + R7 贴图去重）。绝对启动耗时仍需真实服务端实测。
