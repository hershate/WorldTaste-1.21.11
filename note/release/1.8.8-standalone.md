# 1.8.8-standalone

> 性能优化 R5（getDisplayRecipes 不变量缓存 + 静态优化闭合），基于 [1.8.7-standalone](1.8.7-standalone.md)。
> 内容 YAML 不变。完整审查与基准见 [../report/perf/PERF-AUDIT.md](../report/perf/PERF-AUDIT.md) 第 5 轮。

## 版本定位
- 版本：`1.8.8-standalone`（[plugin/build.gradle.kts](../../plugin/build.gradle.kts)、[plugin.yml](../../plugin/src/main/resources/plugin.yml)）。

## 改动（性能，行为不变）

### R5：getDisplayRecipes 不变量缓存
- 核查：`getDisplayRecipes` 仅由指南（SurvivalSlimefunGuide）调用，不在机器 tick 内；recipes 构造后不变。
- `WTRecipeMachine` 首次调用预算展示列表并缓存，后续直接返回（同 R2「提升不变量」原则）。
- 基准（`DisplayBench`，78 配方）：**~90×/次**（269→3 ns）。指南低频，绝对收益小，零风险。

## 评估后未改（低频，无 worthwhile 收益）
- `pushOutputs`（仅合成完成时）、`FoodConsumeListener`/`BlockBreak`（玩家/挖掘事件驱动）：频率受限、实现已精简，不改。

## 静态优化闭合（R1–R5 汇总）
| 轮 | 优化 | 基准收益 |
|---|---|---|
| R1 | 机器配方匹配 SF-id 预筛 + 纯-SF 闸门 | 纯-SF 机器 **~7.5-26×**（isItemSimilar 调用 O(配方数)→O(命中)），非-SF **零回归** |
| R2 | findMatch 每 tick 分配消除（posBySlot int[]） | 绑定槽 **~2.1×**、自由槽 **~17×** |
| R3 | CropBlock growMsSteps 不变量预算；Location 分配消除经实测劣化（0.54×）已拒绝 | 微；负结果存档 |
| R4 | Fishing select total 预算；getById 已 O(1)（MobDrop 缓存不必要） | Fishing **~1.7×** |
| R5 | getDisplayRecipes 不变量缓存 | **~90×/次**（低频） |

结论：所有可静态分析+微基准化的热路径（per-tick / 事件驱动 / 低频）均已覆盖；R3–R5 连续表明优化空间饱和。
**静态性能优化闭合。** 绝对 TPS 需真实服务端实测（本环境无服务端，见 [../server-verification-checklist.md](../server-verification-checklist.md)）。

## 安全性 / 保真度（红线）
- 所有改动均为「行为保持的性能优化」：SF-id 预筛仅跳过确定不匹配者（保 RSC 保真度）；不变量预算/缓存数值与原一致；
  拒绝了会引入 CPU 劣化的 Location 方案。逐条 try/catch、stillValid 复校、RNG 等既有防护均不变。
